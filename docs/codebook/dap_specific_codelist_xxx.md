## Metadata

| Table name                | dap_specific_codelist_<cdm_table> (where <cdm_table> is an events, medicines, vaccines or procedures)                                                                                                                                                                                                                                                                                                                   |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description               | A post-processed version of the VAC4EU (CDM) codelist tailored to a specific Data Access Provider (DAP). <br>It bridges the gap between study-defined codes and actual codes found in the database. <br><br>For hierarchical systems (ATC, ICD), it maps granular database codes to their parent concepts in the `codelist`. This table serves as the final reference for creating the concept instances (D3_CONCEPTS). |
| Source                    | - `dap_codes` (extracted from CDM tables) and <br>- `codelist` (study-defined VAC4EU `codelist`).                                                                                                                                                                                                                                                                                                                       |
| Step                      | `transformations/T2_study_variables/process_codelist.R`                                                                                                                                                                                                                                                                                                                                                                 |
| Population                | All unique codes found in the DAP's data instances **and** all codes required by the study `codelist`.                                                                                                                                                                                                                                                                                                                  |
| Unit of Observation (UoO) | Unique combination of `coding_system`, `code.dap_codes`, and `concept_id`.                                                                                                                                                                                                                                                                                                                                              |

## Processing Steps
| Step number |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Step 1      | Calculates the list of distinct code (dap_codes): <br><br>- For the EVENTS, use the combination of `event_code` and `event_record_vocabulary`. <br><br>- For MEDICINES, use '`medicinal_product_atc_code`' and assign `coding_system` = ATC or PRODCODEID, depending on the DEAP. <br><br>- For VACCINES, use `vx_code` and assign `codinbg_system = ATC`. <br><br>The result should add the `COUNT` column, showing the times a code in combination with the coding system appears in the data instance. |
| Step 2      | Take the `study_codelist` table select `concept_id`, `code`, `coding_system` and `tags` (later two if available), <br>remove duplicate rows, <br>then create a new column priority where rows with tags equal to `"narrow"` get `priority` 1 and all others assign 2. <br>Finally, keep only the columns `concept_id`, `code`, `coding_system`, `tags`, and `priority`.                                                                                                                             |
| Step 3      | **Standardization:** Create `code.codelist` and `code.dap_codes` from the original `code` columns to distinguish sources.                                                                                                                                                                                                                                                                                                                                                                               |
| Step 4      | **Length Calculation:** Calculate `length_str` for the study `codelist` and identify `min_length_codelist`.                                                                                                                                                                                                                                                                                                                                                                                             |
| Step 5      | **Data Splitting:** Divide data into "Exact Match" systems and "Start-With" hierarchical systems (e.g., ATC, ICD).                                                                                                                                                                                                                                                                                                                                                                                      |
| Step 6      | **Exact Matching:** Merge DAP and Study codes where coding systems do not allow prefix matching.                                                                                                                                                                                                                                                                                                                                                                                                        |
| Step 7      | **Start-With Expansion:** For hierarchical codes, generate all possible parent substrings for each DAP code (from min study length to max DAP length).                                                                                                                                                                                                                                                                                                                                                  |
| Step 8      | **Hierarchical Join:** Merge expanded DAP substrings with the study codelist on `coding_system`, `substring`, and `length_str`.                                                                                                                                                                                                                                                                                                                                                                         |
| Step 9      | **Tie-Breaking:** If a DAP code matches multiple study codes, sort by `length_str` (Descending - longest match) then `priority` (Ascending).                                                                                                                                                                                                                                                                                                                                                            |
| Step 10     | **Deduplication:** Keep only the single best match per unique DAP code using `.SD[1]`.                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Step 11     | **Empty Table Safety:** Initialize `all_matches` with correct schema to handle cases where no matches are found.                                                                                                                                                                                                                                                                                                                                                                                        |
| Step 12     | **Gap Analysis:** Perform anti-joins to identify `missing_from_cdm` (Only in Data) and `missing_from_codelist` (Only in Study).                                                                                                                                                                                                                                                                                                                                                                         |
| Step 13     | **Final Stack:** Combine matches and missing records using `rbindlist` with `fill = TRUE`.                                                                                                                                                                                                                                                                                                                                                                                                              |
| Step 14     | **Status Labelling:** Assign `match_status` as `'MATCHED'`, `'ONLY_IN_DATA',` or `'ONLY_IN_CODELIST'.`                                                                                                                                                                                                                                                                                                                                                                                                  |
| Step 15     | **Unified Code:** Populate the final `code` column for matched records using `code.dap_codes`.                                                                                                                                                                                                                                                                                                                                                                                                          |
| Step 18     | **Column Cleanup:** Ensure all requested output columns exist (filling with `NA` if necessary) and return the final table.                                                                                                                                                                                                                                                                                                                                                                              |
